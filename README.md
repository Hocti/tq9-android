# 三三正體中文輸入法 ThreeThree (Android)

使用**已過期**專利 HK1035043 製作的 numpad 式中文輸入法，
由 Windows 版改寫成 Android system keyboard (Kotlin)。

> 名字：全名「三三正體中文輸入法」，通常叫「三三輸入法」，簡稱「三三」；
> 英文「ThreeThree」，簡稱「TT」。

以 numpad 輸入 2~3 鍵即可開始選字，字碼表、關聯字、同音字全部由一個 sqlite 檔案提供，
可以在 app 內隨時更換。

---

## 按哪裡做甚麼

### 中文 view（本體）

```
[⭐速選/長按簡]   7 8 9   [⚙ bar]
[🔈同音/长按關聯] 4 5 6   [⌫]
[🔡英數]          1 2 3   [␣]
[🌐]            [ 0 ][✖]  [⏎]
```

九宮格完全依照 numpad 排法（7 8 9 在最上），與 Windows 版完全一致。

| 鍵 | 單按 | 長按 |
| --- | --- | --- |
| `0` | 標點 / 姓氏 / 選字 / 下頁（依狀態變化） | **開關標點**（「」（）《》…），即原本 `/` 鍵 |
| `⭐` 左上角 | 速選字表（首頁 = 表 1000，按了 1~9 之後 = 表 1001~1009）；選字時 = 上一頁 | 切換簡體輸出 |
| ↑ 這顆 | **短按與長按的功能均可在設定頁更改**：速選字／簡體開關／emoji／貼上／錄音／AI／無效。短按不得選「無效」，短按與長按也不可以做同一件事 | |
| `🔈` | 同音字**開關**（啟用後會變藍）。只 toggle，不會更換目前的字表 —— 繼續輸入字碼、選字，選字時才彈出該字的同音字表 | 關聯字 |
| `🔡` | 轉英文 view | |
| `🌐` | 轉下一個輸入法 | 開輸入法選擇視窗 |
| `⚙` | 上方工具列：關 → 關聯字 → 工具 → 關 | |
| `⌫` | 未打完的碼 → 刪除一碼；選字中 → 取消；否則才確實刪字 | |
| `␣` | 選字中 = 選第一個；否則入空格 | **按住不放，上下左右拖動可移動 caret** |
| `⏎` | 有碼未打完 = 取消；否則 enter / 送出 | |
| `✖` | 取消 | |

**九宮格長按 = 連按**（`1`~`9`）：長按 `7` 等於輸入兩個 `7`，
所以「長按 `7` 再拉至 `0`」= `770`；滑到最後一格稍作停留後才放手都一樣算兩下
（`8` 拉至 `1` 稍作停留 = `811`）。`0` 沒有這個行為，因為它長按是開關標點。

**第二頁開始由中間格排起**：**第一頁永遠由 `1` 排到 `9`**（那個格號就是字碼
最後那個數字，熟練後不會變，沒有任何例外）。**第二頁開始**才跟
`5 4 6 2 8 1 3 7 9` —— 排第一那個坐中央格（最容易按），然後四邊，四角排最後；
該頁得三字就只會佔用 `5 4 6`。第二頁那些字本來就沒有碼可以記，必須看著鍵盤選擇，
所以優先安排在容易按的位置。

**同音鍵左下角一個位置顯示三種內容**（左上角位置留給「長按做甚麼」）：展開同音字表
時會顯示目前查詢哪個字的同音（成頁都是同音字，若不顯示該字，就無法知道查詢哪個）；
平時就顯示**目前已經按了的碼**（`1` → `12` → `123`，設定頁「顯示目前已輸入碼」
可關閉，預設開）—— 輸入滿三碼入了選字模式都仍顯示，不會在按下第三個碼後立即消失，
看不到自己按過甚麼；選完字就換成該字**正確應該如何輸入**（字碼），下次不用再繞道
同音字，再輸入一個普通字就自動清走。

**選字達兩頁**時，兩格寬的 `0` 會變成翻頁鍵。排法可在設定頁選擇（「一般 → 選字翻頁」）：

| 排法 | 底行 |
| --- | --- |
| **大格「下頁」**（預設） | 兩格均為「下頁」（容易按中），**長按同一個 = 上頁**。這個狀態下長按的 `「」` 暫時失效，位置改為在**左上角**細字顯示「上頁」，頁數（`1/10`）搬去**右上角** |
| 拆兩個：上頁、下頁 | 拆分為兩個正常寬，「上頁」在左 |
| 拆兩個：下頁、上頁 | 拆分為兩個正常寬，「下頁」在左 |

使用兩個分頁鍵的兩種排法中，「下頁」鍵**左上角**顯示 `1/10`（目前第幾頁／總共幾頁，由 1 起計）。

`🎤` 錄音已移至上方工具列（在 `📋` 旁邊），左上角該鍵也可選做錄音。

### 上方工具列（按 `⚙` 轉）

共有三種模式，**每種模式都只有一行**，所以切換時鍵盤都不會跳高跳低：

| 段 | 內有甚麼 |
| --- | --- |
| **關** | 沒有，將全部高度留給鍵盤 |
| **關聯字** | 選字／選關聯字，一行無法容納所有內容就右邊會多了一個 `▼`，按它拉開變 scroll view（可完整顯示就沒有該按鍵）。**沒有字碼或關聯字時不會留空，會出速選字**，按一下即可輸入 |
| **工具** | `↔` 大小位置、`📋` 貼上、`🎤` 錄音、`😀` emoji、`✨` AI |

輸入一個字之後，關聯字會直接出在關聯字那工具列（不會再顯示於九宮格中）。

開啟 emoji 表或剪貼簿時，工具列最左會多了一個 **`✖`**，按它就返回普通鍵盤
（就算你平時將工具列關閉，這兩個模式都一定會重新顯示，仍可返回）。

英文完成一次滑動輸入後會**自動重新顯示出關聯字那段**（就算你平時放了在工具段或者關閉），
讓使用者可立即選擇第二個可能的字。

工具列那五個：

- **`↔` 大小位置** —— 按一下轉顯示方式；**上下拖動 = 拉高／拉低整個鍵盤**，
  **左右拖 = 拉寬／拉窄鍵盤本體**（靠左／靠右那兩種顯示方式中才有效），
  **長按（按住不拉）= 一下子拉到最寬**。鍵盤永遠貼近螢幕底，不會整個提起留下空隙在下面。
  本體最窄都會保持 320dp（螢幕本身窄過 320dp 就用盡螢幕）。
  **大小分開以多組設定分別儲存**：中文＋純數字一套、英文＋符號另一套，而且再按時的
  螢幕尺寸分別儲存（摺機內外屏、直向橫向各自一套），所以在哪一個畫面調整，
  就只影響那個畫面那組鍵盤。
- **`📋` 貼上** —— 按一下貼 clipboard；**長按**鍵盤下方就會顯示 clipboard 歷史 scroll view，
  按一行即可貼上，長按一行就可將該項目從歷史記錄刪除。
- **`🎤` 錄音** —— 系統語音輸入（預設 `yue-Hant-HK` 廣東話），正在聽取時，按鍵會亮起。
  設定頁開啟 **AI 語音輸入**就會改用 Gemini 辨識（下面有）。
- **`😀` emoji** —— 開 emoji 表（下面有）。
- **`✨` AI** —— 要**目前確實選取一段字**才能按下，否則會顯示為灰色。
  尚未輸入 API key、或者設定頁關閉「AI 改寫」總開關，整個按鍵都不會顯示。

### Emoji

分類 tab（表情／手勢／人物／動植物／食物／活動／旅遊／物件／符號／旗幟）＋「最近用過」，
`assets/emoji.txt` 包含一千四百多個，載入時會用 `Paint.hasGlyph()` 過濾裝置字型不支援的項目，
不會出豆腐字。

**返回**：按上方工具列的 `✖`。

**找字**：按 emoji 表左上角的 `⌕`（單色，不用彩色 emoji 🔍）就會轉去英文鍵盤，
輸入的文字**不會寫入欄位**，只會即時篩選 emoji，符合的結果出在上方工具列中點選。
找字模式的英文鍵盤**底行只有「退出表情搜尋」和 `␣` 兩個** ——
`?123`、`中`、`⏎`、標點在該頁一個都用不著。

### AI 改寫

在任何 app 選取一段字，按 `✨` 就會傳送至 Gemini，改完直接取代選了那段。
API key、模型（預設 `gemini-3.7-flash`）、prompt（`%text%` = 選了那段字）
均在設定頁輸入。整個功能有總開關，關閉連 `✨` 按鍵也不會顯示。

### AI 語音輸入

設定頁「AI → 語音輸入 (STT)」開啟後，顆 `🎤` 就不再用系統那個語音輸入，
改為錄一段 WAV 掟上 Gemini 辨識。

- **按一下開始錄，再按一次（或輕觸畫面）停**；**按住 `🎤` 不放手**就持續錄，放手即停。
- 錄音及等待結果期間，**整個鍵盤變灰並無法操作**：錄音時中間出計時器，等結果時出載入動畫。
- **開始錄音、錄音結束、成功、失敗四種不同的提示音**（與「按鍵聲音」開關沒有關係）。
- 送上去的還有輸入框目前的內容做**上下文**（純粹讓 AI 了解語境，不會重複輸出）。
- prompt 可修改，預設那個已明確要求「只輸出結果、逐字轉錄不要潤飾、只用繁體字」。
- 錄音最長 90 秒；**只有 Gemini 支援**，開啟後「使用自訂 API」就無法使用。

### 其他 view

| view | 何時出 | 特點 |
| --- | --- | --- |
| 英文 | 按 `🔡`，或者 URI／密碼欄 | QWERTY + Swipe 畫線；長按出變體 popup；`中` 按鍵隨時轉回中文；底行有 `/`；設定內可以在最上面加一行真數字 |
| emoji | 按工具列`😀`（或者左上角該設定了做 emoji） | 分類 tab + 用字找 |
| 數 + 符號 | 按 `?123` | 五行，第一頁可輸入一般 QWERTY 鍵盤上的所有常用符號 |
| 純數 | 符號頁按 `123`；或系統將欄位標記為 number / phone / datetime | 五欄：最左一欄 `+ - * /`，`0` 右邊有顆 `000`。寬度／靠左靠右依照中文九宮格。輸入一個數字後**不會**重新顯示回英文頁，一個接一個持續輸入。PIN 欄（`numberPassword`）會鎖住，不允許切換去其他 view |

**所有鍵盤都總高度一致**（中文四行、英文四／五行、符號五行）：行數較多時，每行會稍矮，
轉來轉去整視窗都不會跳高跳低。

英文鍵盤還有：

- **`a` 左邊與 `l` 右邊沒有死位**，整行九顆鍵用盡整行寬度。
- **連按兩下 `⇧` = capslock**（顆按鍵變藍，輸入任何字母都會使用大寫），長按一樣是 capslock。
- 沒有數字行時，`qwertyuiop` **左上角顯示小號數字、右上角寫符號**；
  開啟後數字行就只在數字鍵右上角寫符號，長按字母也不會再出數字。

**email 欄**（`textEmailAddress` / `textWebEmailAddress`）會自動轉去英文 view，
而且底行會出 `@` 與 `.com`。

## 打錯字想查詢原因：`scripts/debug-input.sh`

```bash
./scripts/debug-input.sh --install   # build + 裝 debug APK，然後立即收 log
./scripts/debug-input.sh --off       # 查詢完成後關閉（日誌 顯示你輸入中的甚麼）
```

`adb logcat -s TTInput` 加入著色和分段，逐行對照**手指做了甚麼**（按下哪個鍵、
坐標、是否因按中隙位而校正至旁邊的按鍵、滑動每格如何計分）以及**輸入法收到甚麼**
（字碼如何逐步變化、選了第幾頁第幾格、出現了哪個字）。開關在設定頁
「其他 → 記錄輸入過程 (logcat)」，或者 `adb shell setprop log.tag.TTInput DEBUG`，
預設兩個都關閉。

## Swipe 畫線

英文與中文都支援。起點和終點一定計，中間格靠三項線索綜合判斷：

1. **停留** —— 在格上面慢了／停低（減速再加速走）
2. **轉角** —— 進入和離開按鍵格的**即時**方向差異夠大
   （特意不用「入口→出口」弦線，因為 90° 轉角用弦線只會計到 45°）
3. **字碼表 weight** —— `mapped_table.weight` 表示這文字碼有幾常用。
   純幾何不確定時（例如轉角不夠深）就靠它加減分：
   已加入這一碼之後完全沒有字 → 直接排除；是常見字碼 → 補回分。

```
分數 = 幾何信心(0~1) + 0.35 × weight信心(-1~+1)，  ≥ 0.62 就當按了
```

中文是**即時出碼**：滑過 `7→9→3` 畫一個直角，等於順序按了三下，
每出一碼九宮格的內容就立即變（不是放手先統一計算），
所以以一筆輸入完整一個字（甚至進入選字）是可行的。

英文就相反，放手才組成單字。第一個字會用 composing text 寫入，
其餘關聯字出在上方工具列，按一下就換。

英文滑動還有兩項功能：

- **滑多一次 = 下一個字**：會自動加入空格再開新字，不會覆蓋上一個字。
- **會看 caret 前後**：欄位本身是 `dis|y`（`|` = caret），滑 `p→l→a` 就會出 `display` ——
  只找「`dis` 開頭、`y` 結尾、中間可容納滑過那些字母」的字，出錯率大幅降低。

### 英文詞庫

`assets/en_freq.txt` —— 20 萬個最常用英文字及其使用頻率
（來自 `/mnt/d/sync_dev/eng/data/en-most.txt`，過濾非 a-z 之後）。

- **不會在開機或開啟鍵盤時載入**。第一次見到英文 view 才會在低優先級背景執行緒中載入，
  實測模擬器 **108ms** 完成載入 199,997 文字。未載完就當沒有提示，UI 完全不會 lag。
- 慳記憶體：將所有字串接做一條 string + offset array，不是 20 萬個 String object，
  比對直接直接在其中比對，不用 substring。
- 選字 = `使用頻率(ln) − 長度差罰分`，首尾字母一定要正確，中間要是 subsequence。
  即多個字均符合時，會選擇**最常用**那個
  （`t-h-e` → `the`、`a-n-d` → `and`），中間遺漏鍵一樣仍能符合
  （`h-l-o` 都可選擇 `hello`）。

靈敏度（停留時間、轉多少度）可在設定頁調整。

### 英文長按變體

同一般英文鍵盤一樣：長按後彈出一行變體，**不要放手**，左右拉去選，放手才輸入。

- **數字鍵**：與實體鍵盤按住 Shift 相同（`1` → `!`、`2` → `@`…），
  `4` 不止 `$`，各國貨幣符號都可選（`£ € ¥ ¢ ₩ ₹ ₱`）。
- **字母**：沒有數字行時 `qwertyuiop` 會顯示數字與符號（`q` → `1` `!`）；
  開啟後數字行就只保留各國重音寫法（`a` → `á à â ä ã å ā æ`、`c` → `ç ć č ©`…）
- 選哪一個是看**手指移動了多遠**，不是絕對位置 —— 彈出時就已經選取第一個，
  所以想要數字就長按後直接放手，不用拖。變體多到整行擠至邊緣都可選擇第一個。

## 顯示方式（寬螢幕 專用）

摺機、平板、橫向時，如果任由九宮格拉寬，按鍵格會變成長方形，又難按又難 swipe。
所以本體超過設定內的 **最大寬度／最大高度** 之後就會定形，剩餘空間由使用者決定如何分配：

| 模式 | 效果 |
| --- | --- |
| `↔` 拉長 | 用盡整行（細螢幕預設） |
| `⬅` 左留白 | 鍵盤貼右，左邊留白 |
| `➡` 右留白 | 鍵盤貼左，右邊留白 |
| `⫽` 左右拆開 | **英數鍵盤 + 螢幕寬度超過 500dp 先有**：每行鍵分成兩半，一半貼左、一半貼右，中間留白（橫向兩隻拇指各顧一邊）。space 會拆做兩條，左右各一 |

工具列最左該按鍵即時切換（改的是時正在顯示那組鍵盤），設定頁的按鍵改中文那組。
**螢幕寬度超過 500dp 的英數鍵盤只有「拉長」與「左右拆開」兩個**——
這麼寬的螢幕靠近一邊，另一邊那大片位就是浪費了。

英數鍵盤的寬度可以由**最窄 320dp（螢幕本身窄過就用盡螢幕）拉到整個螢幕這麼寬**，
中間按比例調整；拆開模式就是那個寬度分成兩半，兩半各一半。

**高度就與顯示方式無關**：鍵盤永遠用盡分配到的高度、永遠貼近底，
想高些矮些就在該按鍵度**上下拖動**（或者設定頁的「鍵盤高度」）。

## 設定頁（app 本身）

- **字碼資料庫**：browse 選一個 sqlite 檔案 → **直接覆蓋**目前那個（舊版不會保留）。
  匯入前會檢查是否具有 `mapped_table` / `related_candidates_table` / `ts_chinese_table` / `word_meta`
  四張表，不正確就不會換。另外有「還原內置字碼表」。
  **如未自行更換，每次升級都會自動換上新版內置表**（過去會一直沿用首次安裝時的版本，
  因此新版字碼表的修改不會生效）；自行選取 sqlite 後，系統會視之為使用者自訂內容，升級時不會覆蓋，
  要按「還原內置字碼表」先恢復。還有「檢視目前 sqlite…」＝ save as 一份出去，
  使用者自己選應用程式開來看（筆形提示圖那一節也有）。
- **鍵盤大小**：按鍵空隙、**字體大小（中文鍵盤一條 70~140%；英文鍵盤一條 70~200%，
  而且繪製時仍會乘 `Prefs.LATIN_FONT_BOOST` = 1.2）**。長寬和顯示方式一律在鍵盤上
  拖動工具列最左顆按鍵調整，設定頁**沒有**這些選項（其餘尺寸 slider 已隱藏，code 沒有刪）
- **按鍵功能**：左上角該鍵短按／長按分別做甚麼（速選字／簡體／emoji／貼上／錄音／AI；
  短按不得選「無效」，短按與長按也不可以做同一件事）、英文鍵盤要不要加一行數字
- **滑動輸入**：開關 ＋「停留多久當作按下」「轉多少度當作轉角」兩條門檻
  （隱藏過一排，2026-08-31 重新顯示做 debug 測試用）
- **選字翻頁**：翻頁鍵三種排法（大格「下頁」＋長按上頁／拆兩個兩種次序）
- **AI**（分三大類，每類均可收合）：**語音輸入 (STT)**（開關＋prompt）、
  **AI 改寫**（開關＋prompt）、**AI 設定**（API key、模型、自訂 API、profile）
- **使用習慣統計**：`usage_stats.db`（每字打過多少次 + 前後兩個字的組合）
  匯出／匯入／清除，以及「**常用字排前**」開關（預設開；**第一頁永遠保持不變**，
  第 10 個字起才排。關閉仍然繼續記數，只是不用於排關聯字）
- **其他**：簡體輸出、上方工具列啟動時的預設是哪一段、**震動強度（0～3 級 slider）**、
  按鍵聲、長按時間（逐 10ms 一格）；底部顯示目前的版本號
- **試打**：四欄位（普通／email／PIN／搜尋）直接試用
- **預覽**：實時九宮格，調整尺寸後立即顯示變化

## 資料庫

與 Windows 版完全一樣，直接照用 `files/dataset.db`：

| table | 用途 |
| --- | --- |
| `mapped_table` | `id` 0 = 標點，1 = 開關標點，10~999 = 字碼表，1000~1009 = 速選字表；`weight` = 常用度（swipe 判斷會用） |
| `related_candidates_table` | 關聯字，用空格分隔 |
| `ts_chinese_table` | 繁→簡 |
| `word_meta` | 同音字（`ping` / `ping2`） |

字碼會拆成 grapheme cluster（與 C# 的 `StringInfo` 一樣），所以 emoji、香港增補字符集都食得住。

九宮格按鍵格預設**不是正方**，高度是寬度的 80%（正方在手機上面太高），設定內可以調回。

筆形提示圖是**一幅** sprite sheet：`assets/default90.png`，橫 9 直 10 共 90 格
（左上 `0_1`、右上 `0_9`、左下 `9_1`、右下 `9_9`），繪製時即時取得 source rect
出來畫，不會 decode 90 個 Bitmap。可在設定頁更換這幅圖（更換後的圖片放在
`filesDir/strokes.png`，「還原內置圖片」＝刪除該檔案），處理方式與更換 `dataset.db` 一樣。
Android 版**不需要** `10_1`~`10_9`，因為關聯字已改在上方工具列選。
App icon 由 `../logo.jpg`（2048×2048）縮出來 —— mipmap 五個 density 的
`ic_launcher_foreground`（透明底，圖佔 canvas 50%，圓形 mask 都不會切到）
以及 legacy 的 `ic_launcher` / `ic_launcher_round`，底色見 `values/colors.xml`。

## 建置

```bash
./gradlew assembleDebug          # app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest      # swipe 判定 + 英文詞庫（連真實 20 萬字數據）的 unit test
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell ime enable tt.ime.riverine/.ime.TTInputMethodService
adb shell ime set    tt.ime.riverine/.ime.TTInputMethodService
```

minSdk 26 / targetSdk 36 / Kotlin 2.1 / AGP 8.13。

系統的輸入法清單中只有**一個**「三三」（中英數符號是在鍵盤內自己切，不用分 subtype）。

開發／改內容之前請看 [AGENTS.md](AGENTS.md)，其中記錄了已知問題和注意事項。

> 在模擬器上測試，請記得 `adb shell settings put secure show_ime_with_hard_keyboard 1`，
> 否則模擬器會因識別到實體鍵盤而不會彈輸入法出來。
